# WhatsApp: five chats, ten messages each, on the desktop

The first desktop task through the task API
(`crates/tinycomputer-examples/tasks/whatsapp/`): read the five most recent
chats in the WhatsApp app on macOS and return each chat's name and its ten
most recent messages as JSON. Replayed plan, deep deliberation, up to five
rescues, run on the host with the Accessibility permission. Message content
is personal data and is not recorded here.

## Runs

| Run | What changed before it | Outcome | Time | Rescues |
|---|---|---|---|---|
| 1 | first run, `open` by name | failed: `APP_NOT_FOUND` | 6 s | 0 |
| 2 | `open` by bundle id; flat lists for `extract` | finished, but a chat skipped, one read twice, a group's member line read as its name | 2.5 min | 4 |
| 3 | "open the chat just below `${chat_n}`" | failed: 5 rescues spent | 1.8 min | 5 |
| 4 | row-numbered steps; `read` offers name and value apart; output pass | failed: 5 rescues spent | 2.5 min | 5 |
| 5 | `pick` the chat nearest the top not already collected; `already_collected` memory; a judged `pick` chooses its list | finished, one chat read twice after a rescue | 55 s | 1 |
| 6 | saved values carried into every run (`RunFlowRequest.collected`) and the rescuer's briefing | **finished, five distinct chats in list order, result fits the schema** | 60 s | 1 |

Run 6: 193 Jev calls on 0.99 M input tokens (about $0.04 at $0.042 per
million, output free), 7 actions, one rescue and one shaping call on
GPT 6 Luna. The result held 8, 7, 10, 5, and 9 messages: one chat had 15 on
screen and was cut to ten; the others showed fewer than ten, because
`extract` reads what is on screen and does not scroll.

## What failed, and why

- **Opening the app.** Its bundle is named `‎WhatsApp.app`, with a leading
  left-to-right mark; `NSWorkspace` finds no application named "WhatsApp".
  The bundle id works. The name lookup belongs to `vendor/agent-desktop`.
- **`extract` found no list.** A desktop tree labels no container with an
  ordinal the way a web page's `listitem #3` is; messages are a run of text
  siblings. Such runs are now lists (`MIN_FLAT_ITEMS`).
- **Positional steps looped.** An open chat's row stops being a button named
  for the chat and shows only its last message. Jev scored "the first chat is
  open" at 0.40 with it open, and at 0.75 once the next chat was open, so
  "open the Nth chat" never settled.
- **The run forgot what it had read.** Jev's state named the variables read,
  never their values, so "the next chat not yet read" could not be judged;
  and a rescue started a run that forgot even those. The memory, and
  carrying it across runs, fixed runs 5 and 6
  ([`../specs/task-output.md`](../specs/task-output.md)).
